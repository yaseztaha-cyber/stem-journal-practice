# Shipping updates to installed apps

The desktop app checks for updates on startup and from Settings → App
updates. Updates install automatically when the user quits.

## One-time hosting setup

1. Pick any static HTTPS host (school server, GitHub Pages/Releases,
   Cloudflare R2, Netlify…).
2. After any release build, upload the whole `release/` output for that
   version, especially:
   - `STEM Journal Practice Setup 1.0.0.exe`
   - `latest.yml` (generated by electron-builder because `publish` is set)
   - `*.blockmap` files (enable small delta downloads)
3. Put the public folder URL into `desktop/update-feed.json`:
   `{ "url": "https://your-host/sjp/updates/" }`
4. Rebuild once so the feed ships inside the app.

Until step 3 is done, the app reports "unavailable" instead of erroring.

## Releasing a patch

```
cd desktop
npm run release        # bumps patch version (1.0.0 -> 1.0.1) + full dist
```

Then upload the new `release/` files to the same feed URL. Installed apps
on older versions pick it up, download in the background, and install on
quit. Major/minor: `npm run release -- minor` (or `major`).

## Notes

- Version comes from `desktop/package.json` — never ship two different
  builds with the same version number.
- Unsigned builds (current) show a Windows SmartScreen prompt on first
  install; updates to an installed app do not re-prompt.
- The embedded database (`%APPDATA%/stem-journal-practice-desktop/pgdata`)
  is outside the app folder, so updates never touch student data.
